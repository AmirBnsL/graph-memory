# 0003: External Graph Memory Architectures & Diagnostic Generalization

We integrate two external graph memory archetypes—Bipartite Concept Graph (HippoRAG 2) and Dual-Level Graph (LightRAG)—under strict causal isolation to test whether topological diagnostics generalize across diverse graph RAG paradigms.

## Context

Hypothesis 2 established that non-parametric graph metrics ($G_{\text{deg}}$, $\max_v \deg(v)/\bar{d}$, $\rho_{\text{LCC}}$, density, bridge ratio) predict retrieval performance on natural conversational memory graphs. However, our empirical evaluation in H1 and H2 focused primarily on Concept Graph (HippoRAG 1) and Bi-Temporal Event Graph (BTEG). 

To verify whether these topological diagnostic metrics represent universal laws of graph retrieval rather than idiosyncratic properties of our initial representations, we expand our evaluation harness to include state-of-the-art graph memory archetypes from recent literature (2024–2025).

## Decision

We establish four primary methodological decisions for integrating external graph memory architectures:

1. **Candidate Archetype Selection:**
   We benchmark two distinct architectural archetypes:
   - **Bipartite Concept Graph (HippoRAG 2):** Incorporates dialogue turns directly as first-class vertices alongside extracted entities, linked via occurrence edges and traversed via bi-directional Personalized PageRank.
   - **Dual-Level Graph (LightRAG):** Stratifies memory into low-level entity-relation triples and high-level thematic concept nodes formed by semantic clustering of entities.
   
   Cloud-dependent or external database services (e.g., Neo4j-backed Graphiti, Zep Cloud) are kept out of scope to preserve 100% reproducible local execution.

2. **Strict Causal Extraction Invariant:**
   To prevent confounding graph topology with extraction quality or embedding changes:
   - All architectures must strictly consume our existing pre-cached extraction records (`data/cache/extractions/` or `cache/extract/`) generated by `Qwen2.5-7B-Instruct` and `Qwen2.5-14B-Instruct`.
   - All synonymy and seeding must use the fixed retriever embedding model (`Qwen3-Embedding-0.6B`).
   - The reader LLM and benchmark split (`LongMemEval`) remain invariant.

3. **White-Box BaseMemory Implementation:**
   Implementations reside natively in `src/graph_memory/memory/graph/` as subclasses of `BaseMemory`. Each implementation must expose `export_graph() -> nx.Graph` to enable per-sample calculation of the five H2 structural metrics via `compute_graph_metrics()`.

4. **Pre-Registered Directional Hypotheses:**
   We pre-register directional hypotheses testing the regime thresholds from Table 4:
   - **Bipartite Reachability Hypothesis (HippoRAG 2):** Directly embedding turn vertices will elevate global reachability ($\rho_{\text{LCC}} > 0.40$), reducing path fragility. However, conversational turns that cover multiple topics will introduce turn-based mega-hubs that risk triggering the Super-Hub Dominance penalty ($\max_v \deg(v) / \bar{d} > 12.26$).
   - **Thematic Clustering Hypothesis (LightRAG):** High-level thematic nodes will eliminate component fragmentation ($\rho_{\text{LCC}} > 0.24$). However, if thematic clusters act as unconstrained transit hubs, they will concentrate degree inequality ($G_{\text{deg}} > 0.608$) and suffer the predicted PPR sinkhole penalty.

## Consequences

- New memory modes (`memory_hipporag2`, `memory_lightrag`) integrate into the pipeline and automated table generators.
- Both modes generate per-sample graph metrics (`graph_metrics_by_sample`) for seamless incorporation into Hypothesis 2 regression and regime analysis.
- Confirms whether H2 diagnostic metrics generalize across bipartite and hierarchical graph representations without new GPU extraction spending.
